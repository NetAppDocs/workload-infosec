= Least privilege permission tiers for NetApp Workload Factory
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]

You can restrict Workload Factory IAM permissions at any time to align with least-privilege requirements, including:

* Limiting access to specific resources (ARNs)
* Applying IAM conditions (for example, tags and CIDR ranges)

Workload Factory also provides an Ask Me advisory flow that helps you safely refine permissions by suggesting restriction options and generating an updated policy to apply in AWS.

Workload Factory uses a tiered permission model aligned with least privilege.
You choose which capability tiers to enable when adding AWS credentials.
You can start with read-only discovery and expand as needed.

All permissions are granted through an IAM role in your AWS account that Workload Factory assumes via STS with an external ID.
Each API call is further scoped with an inline session policy.

== Granting permissions

When adding AWS credentials to Workload Factory, you can choose which permission tiers to enable.
You can enable or disable tiers at any time.

Tiers are cumulative: enabling a higher tier automatically enables all lower tiers.

== Security controls

* External ID (confused deputy protection)
* Per-operation session policies (least privilege per request)
* Tag-based conditions (security group modifications restricted to Workload Factory-created resources)
* Secret ARN scoping (Secrets Manager access restricted to `FSxSecret*`)
* Runtime permission validation (missing action/resource reported for targeted remediation)

=== Tier 3 (file system creation) permissions

Tier 3 permissions enable provisioning and deprovisioning of FSx for ONTAP file systems and storage VMs.

[cols="2,3,3",options="header"]
|===
|Permission |Purpose |Impact if removed
|fsx:CreateFileSystem |Provision new FSx for ONTAP file systems |File system creation unavailable
|fsx:DeleteFileSystem |Delete file systems |File system deletion unavailable
|fsx:CreateStorageVirtualMachine |Create storage VMs |SVM creation unavailable
|fsx:DeleteStorageVirtualMachine |Delete storage VMs |SVM deletion unavailable
|fsx:TagResource / fsx:UntagResource |Tag resources during creation |Created resources untagged
|kms:CreateGrant |Allow FSx to use your KMS key for encryption at rest |Encrypted file system creation fails
|kms:DescribeKey / kms:ListKeys / kms:ListAliases |Enumerate available KMS keys for selection |KMS key picker empty
|iam:CreateServiceLinkedRole |Create the FSx service-linked role (one-time) |First file system creation fails if role doesn’t exist
|ec2:CreateSecurityGroup / ec2:CreateTags |Create security group for new file system |File system creation fails
|ec2:DescribeVolumeStatus |Verify underlying storage health |Health checks degraded
|ec2:AuthorizeSecurityGroupEgress / ec2:AuthorizeSecurityGroupIngress |Configure security group rules for ONTAP access |Network rules not applied
|ec2:RevokeSecurityGroupEgress / ec2:RevokeSecurityGroupIngress |Clean up security group rules on deletion |Stale rules remain
|ec2:DeleteSecurityGroup |Remove security group on file system deletion |Orphaned security groups
|===

Resource scope: Security group modification actions (Authorize, Revoke, Delete) are restricted to resources tagged `AppCreator=NetappFSxWF`.
