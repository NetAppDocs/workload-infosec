= Data storage in Workload Factory
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ../media/

[.lead]
Workload Factory data storage considerations include:

* What information is kept
* Where information is held
* How long information is kept
* What information leaves the VPC
* Account deletion considerations

== What information is kept

Workload Factory keeps the following data:

* FSx configuration snapshots (refreshed on each scan)
* ONTAP credentials (AES-encrypted with KMS envelope encryption; persistent until the user deletes)
* EDA metrics
* CloudFormation templates (7-day Expires header)
* AI usage and cost data
* Audit records
* Redis caches (FSx responses) with a 20-minute TTL

== Where information is kept

* AWS account:
** ONTAP admin passwords are stored in your AWS Secrets Manager.
** AI inference (EMS analysis) uses your inference profile ARN through an STS-assumed role and is processed by Amazon Bedrock within your AWS account.
* NetApp account:
** FSx configurations, balance plans, ARP configurations, and AI usage limits
** STS tokens, response caches, locks, and deployment state
** CloudFormation/Terraform templates, WAD config descriptors, and compressed reports
** AI usage metering and collector performance metrics
** EDA aggregated metrics
** Action audit trails
** OpenTelemetry traces
* Region:
** Stored in regions where the Amazon Bedrock service is available.
** NetApp internal operates in us-east-1 and us-west-2.

== How long information is kept

* *ONTAP credentials (MySQL)*: Indefinite, until the user explicitly deletes
* *STS assumed-role tokens (Redis)*: <= 30 minutes (AWS-imposed)
* *FSx response cache (Redis)*: 20 minutes (hardcoded)
* *S3 CloudFormation/Terraform templates*: 7 days (configurable using an environment variable)
* *Auto-capacity retry counters (Redis)*: 1 hour
* *Restore-from-backup tracking*: 7 days (hardcoded)
* *AI usage metrics (Timestream)*: 24 hours hot / 180 days cold (hardcoded)
* *EDA performance metrics (DynamoDB)*: Indefinite (no TTL configured)
* *Audit records*: Governed by the NetApp Console retention policy (not controlled by Workload Factory)
* *CloudWatch logs*: 14 days

== What information leaves the VPC

* *Management plane traffic to the Workload Factory service*: FSx configuration, volume metadata, resource identifiers, and operational commands flow over HTTPS to the Workload Factory service tier for all management operations.
* *Audit records to the NetApp Console Audit Service*: Every tracked operation sends the following information:
** accountId
** actionName
** status
** resourceId
** userId
** requestData
** responseData
** timestamps
** IP address
** workspaceId
* *Amazon Bedrock (stays in your AWS account)*: EMS event details, SVM information, and FSx file system metadata are sent to Bedrock for AI analysis. This uses your inference profile ARN and assumed-role credentials, so data stays within your AWS account boundary (not sent to NetApp).
* *Standard AWS API calls*: FSx, EC2, STS, S3, Secrets Manager. These can be routed through VPC endpoints if configured.
* *OpenTelemetry traces to SigNoz*: Service names, request IDs, latency, and error information. This is cluster-internal within the Workload Factory service VPC and does not leave to external networks.
* *Bedrock traffic stays in your AWS account* (your credentials, your region): Management and audit traffic goes to NetApp-controlled endpoints.
