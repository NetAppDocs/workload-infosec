= Learn about the Ask Me assistant in Workload Factory
:hardbreaks:
:nofooter:
:icons: font

[.lead]
Ask Me is a generative AI-powered intelligent assistant embedded within NetApp Workload Factory. It provides you with real-time, conversational support for Amazon FSx for NetApp ONTAP and Workload Factory topics, including product guidance, best-practice recommendations, and operational queries against their own cloud resources.

Ask Me is designed with security-first principles, ensuring that all generative AI interactions are governed, auditable, and compliant with enterprise-grade security standards.

== Ask Me architecture and security

Generative AI architecture and security in the Ask Me assistant includes retrieval-augmented generation (RAG) and multi-layer prompt security.

=== RAG architecture in Ask Me

Ask Me uses a RAG architecture rather than relying on the LLM's parametric knowledge alone. This is a deliberate security and accuracy decision:

* *Curated knowledge base*: The LLM's responses are grounded in a managed corpus of verified, published NetApp documentation. This significantly reduces the risk of hallucinated or fabricated answers.
* *Retrieval scoring and filtering*: Retrieved content is scored for relevance. Only chunks exceeding a configurable confidence threshold are included in the LLM context, preventing low-quality or irrelevant content from influencing responses.
* *No internet access*: The LLM has no access to the open internet. All source material comes from the curated knowledge base or authorized API integrations. The model cannot fetch, browse, or scrape external content.
* *Source attribution*: Responses include references to the source documents used, enabling users to verify the information independently.

=== Multi-layer prompt security

Ask Me implements a defense-in-depth strategy against prompt-based attacks. Every user query passes through multiple sequential security gates before a generative response is produced:

* *Layer 1: Security classifier (LLM-as-a-judge)*: A dedicated, separate LLM evaluates every inbound query for malicious intent, including prompt injection, privilege escalation, data exfiltration, social engineering, and policy violations. If the query is classified as malicious, it is immediately blocked. The user receives a generic rejection message, and the blocked query is logged for security audit. The generative model never sees the blocked query.
* *Layer 2: System prompt hardening*: The generative model operates under tightly scoped system instructions that cannot be overridden by user input. The LLM is explicitly instructed to refuse any attempt by the user to change its behavior, reveal its instructions, or bypass security policies.
* *Layer 3: Domain scoping*: The LLM is restricted to FSx ONTAP and Workload Factory topics only. Off-topic, harmful, or out-of-scope requests are deflected by design. The model will not produce responses outside its designated domain regardless of how the request is phrased.
* *Layer 4: Tool-use governance*: If the LLM determines it needs to call an external tool or API, all parameters are validated and all resulting data queries are executed within a hardened sandbox (see Section 2.5). The LLM cannot execute arbitrary operations.

Only after passing all four layers is a generative response produced and streamed to the user.

=== Security classification (LLM-as-a-judge)

A separate, dedicated LLM acts as a security classifier for every inbound query. This model is distinct from the model that generates user-facing responses and operates with its own hardened prompt. It evaluates queries for:

* *Prompt injection*: Attempts to override system instructions or inject new directives.
* *Privilege escalation*: Attempts to access data or capabilities beyond the user's scope.
* *Data exfiltration*: Attempts to extract system prompts, internal configuration, or other users' data.
* *Social engineering*: Attempts to manipulate the assistant into revealing sensitive information.
* *Policy violations*: Requests for harmful, inappropriate, or off-topic content.

Queries classified as malicious are immediately blocked. The user receives a generic rejection message. The blocked query, its classification, and the user identity are logged for security audit. The generative model never sees the blocked query.

=== Model data isolation and privacy

* *No model training on customer data*: The managed AI provider contractually guarantees that customer inputs and outputs are not used to train, fine-tune, or improve foundation models.
* *No cross-tenant data leakage*: Each request is stateless from the AI provider's perspective. Model inference is isolated per request; no customer data is retained in model memory between sessions or across users.
* *Conversation history scoping*: Conversation context is maintained only within the user's active session and is never shared across users or sessions. History is bounded by a configurable maximum to limit context window exposure.
* *No persistent model memory*: The LLM does not have persistent memory or learning capabilities. It cannot recall previous sessions or accumulate knowledge about individual users over time.
* *Managed infrastructure*: All model inference runs on fully managed cloud infrastructure with built-in compliance certifications (SOC 2, ISO 27001, HIPAA eligible). No model weights or inference endpoints are self-managed.

=== Tool-use and agentic security

When Ask Me uses tool integrations (for example, querying the customer's own Workload Factory resources), the following security controls apply:

* *Authorization-scoped tools*: Tool calls operate within the scope of the authenticated user's credentials and permissions. A user cannot access resources belonging to another account or tenant.
* *Tool execution timeout*: Every tool call is subject to a strict execution timeout. Long-running or hung operations are forcefully terminated.
* *Ephemeral data sandbox*: Data retrieved through tool calls is stored in a session-scoped, read-only sandbox that is destroyed when the session ends. The sandbox environment disables external access, file I/O, network calls, and extension loading at the engine level.
* *Read-only query enforcement*: Any analytical queries the LLM generates against retrieved data are validated through a strict allowlist. Only read-only operations are permitted. Data modification, system-level commands, and multi-statement injection are blocked.
* *Prompt-enforced and code-enforced security*: Tool security is enforced at two independent layers. The LLM system prompt instructs it to never bypass security rules, and the application code independently validates and blocks prohibited operations regardless of what the LLM generates.
* *Tool call auditability*: Every tool invocation (tool name, parameters, timestamps, result status) is logged for audit. Sensitive parameter values are scrubbed before logging.

=== Output controls

* *Token limit enforcement*: Responses are bounded by a configurable maximum token limit, preventing unbounded or resource-exhausting generation.
* *Temperature control*: Classification and security-critical operations use zero temperature (deterministic output), eliminating randomness in security decisions.
* *Streaming with early termination*: Users can stop a response mid-stream. Cancellation is handled gracefully, and all associated background operations are cleaned up.
