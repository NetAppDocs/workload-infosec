= Learn about AWS Bedrock usage in Workload Factory
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ../media/

[.lead]
Workload Factory uses Amazon Bedrock for AI-powered storage event analysis and latency diagnostics. Bedrock inference runs in your AWS account using your credentials and your inference profile.

There are many reasons to send data to Bedrock for analysis, but Workload Factory limits the data sent to only what is necessary for specific AI features. The following sections describe what data is sent to Bedrock, and what data is not sent.

== For latency analysis

* File system deployment information (generation, type, throughput capacity)
* Volume configuration (name, size, aggregate placement, QoS policy)
* Real-time performance metrics (QoS workload statistics, per-volume latency breakdown)
* Aggregate capacity and utilization
* Network interface (LIF) configuration
* Connected NFS client information
* Recent ONTAP events (last 24 hours, severity NOTICE and above)

== For EMS event analysis

* The EMS event message and catalog details
* Storage VM (SVM) information
* FSx file system metadata from AWS

== What is not sent

* File content or file names
* User data stored on volumes
* AWS access keys or credentials
* Customer-identifiable information beyond resource IDs
