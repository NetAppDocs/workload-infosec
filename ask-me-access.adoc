= Ask Me authentication and access control in NetApp Workload Factory
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ../media/

[.lead]
Ask Me access security in Workload Factory centers on authenticated sessions, user-level accountability, and protected secret handling during runtime operations.

* *Industry-standard token authentication*: Every request is authenticated using signed JWT tokens validated with cryptographic key verification, including audience, issuer, and algorithm checks (RS256).
* *Middleware-enforced authentication*: Authentication is enforced at the service boundary. Unauthenticated or expired tokens are rejected before reaching any application logic or generative AI pipeline.
* *User identity scoping*: Each authenticated session carries a verified user identity, ensuring that all generative AI interactions and logs are attributable to a specific user.

== Credential protection and secret handling

* *Secure vault storage*: All sensitive credentials used by the service are stored in a managed secrets vault and retrieved at runtime. No secrets are stored in application code, configuration files, or container images.
* *Log scrubbing*: A configurable mechanism automatically redacts sensitive values (credentials, tokens, passwords, access keys, certificates) from all application logs before they are written.

== Ask Me infrastructure security

Ask Me in Workload Factory includes the following infrastructure security features:

* *Non-root container execution*: The application runs as a non-root user, following the principle of least privilege.
* *CORS restrictions*: Cross-Origin Resource Sharing is restricted to an explicit allowlist of trusted NetApp domains only.
