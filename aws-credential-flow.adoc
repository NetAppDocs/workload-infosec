= AWS credential flow for NetApp Workload Factory
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]

This AWS credential flow shows how role identifiers, external IDs, and short-lived AWS STS credentials are handled during onboarding and runtime operations. During one-time setup, you create an IAM role in your AWS account and configure its trust policy to require the Workload Factory service principal and the correct external ID. Workload Factory stores the role ARN and external ID in encrypted form, then uses them at runtime to request temporary credentials for each AWS API operation. A per-request session policy limits the permissions for those credentials to the actions required for the operation, while cached credentials can be reused until they expire.

== Credential data flow and retention path

The following diagram illustrates the flow of AWS credentials and how they are retained in Workload Factory.

image::workflow-4.png[Workflow 4: AWS credentials flow (STS AssumeRole and session policies)]

== One-time setup
For a one-time setup, the flow is as follows: 

.Steps
. The user launches a CloudFormation stack or manually creates an IAM role in your AWS account.
. The IAM role trust policy specifies two conditions:
.. Only the service principal for Workload Factory can assume it.
.. The caller must present the correct external ID.
. Workload Factory stores the role ARN and external ID (encrypted) in its database.

== Runtime (every API operation)
At runtime, Workload Factory uses the stored role ARN and external ID to obtain temporary AWS STS credentials for each API operation. The flow is as follows:

. Workload Factory retrieves the stored role ARN and external ID from MySQL.
. It checks Redis for a cached set of temporary AWS STS credentials for this role.
. On cache miss, Workload Factory calls `sts:AssumeRole` with the role ARN, external ID, and a per-request inline session policy that restricts permissions to only the specific AWS actions needed for that operation.
. AWS STS returns temporary credentials (access key ID, secret access key, session token) with an expiration timestamp.
. Workload Factory caches these credentials in Redis and uses them to call the target AWS APIs.
. On cache hit, Workload Factory skips the STS call and uses the cached credentials directly.

== Session policy 

Each STS call includes an inline session policy scoped to the minimum AWS actions required.
