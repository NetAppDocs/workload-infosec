= Access Workload Factory AWS account
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ../media/

[.lead]
Workload Factory uses AWS `sts:AssumeRole` to obtain temporary credentials for your AWS account, so long-term AWS access keys are not stored by the service.

[role="tabbed-block"]
====
.Configuration
--
To enable Workload Factory access to your AWS account, deploy an IAM role, and register it with Workload Factory.

.Steps

. Deploy an IAM role in your AWS account (using CloudFormation or manually).
. Ensure the role's trust policy allows Workload Factory's service principal to assume it, gated by an external ID.
. Use an external ID as a unique secret identifier (UUID v4) shared exclusively between the customer and Workload Factory. It is embedded as a condition in your IAM role trust policy (`sts:ExternalId`).
+
The external ID prevents confused deputy attacks. In a cross-account access model, an attacker who discovers a customer's role ARN cannot assume that role without also possessing the corresponding external ID. This is the AWS-recommended pattern for third-party cross-account access.
+
For more information, see AWS documentation: link:https://aws.amazon.com/[How to use an external ID when granting access to your AWS resources].
+
The external ID is generated once during credential onboarding and stored encrypted alongside the role ARN in Workload Factory's database.
. Register the role ARN and external ID in Workload Factory.
--

.Runtime
--
At runtime, Workload Factory assumes your IAM role to obtain short-lived credentials for each AWS API operation.

.Steps

. Workload Factory calls `sts:AssumeRole` with your role ARN and the external ID.
. AWS returns temporary credentials (access key, secret key, and session token).
. These temporary credentials are used for all AWS API operations in your account.
. Credentials expire automatically (by default, 1 hour).
--
